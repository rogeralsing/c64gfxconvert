# Fused HC64 character player

This native PAL player shows the shared 64-frame checker sequence from the compact HC64 file. It uses the original fixed mathematical font. It performs no runtime projection or polygon rendering.

See the [shared playback experiment](../README.md) for the current assets and player comparison. The smooth-motion HC64 file is 19,096 bytes and contains at most 187 edge glyphs per frame. It advances yaw by 0.9375 degrees per frame at fixed pitch 22 degrees and roll 12 degrees. The 64-frame loop closes through the checker's 60-degree pattern symmetry.

The decoder expands each PackBits fill payload into 60 bytes. It then reads fill bits and the raw edge-presence map together. Each selected character receives either glyph 0/15 or the next exact edge glyph, with one final screen write per cell. The 475 cells are visited in the serialized row-span order; the five unused tail bits are ignored.

Two direct-store kernels target the two screen buffers. Their destination addresses are generated at assembly time from the HC64 file's 50 row-layout bytes. They contain no per-frame glyph values, images or animation deltas. The two kernels and the fill lookup table trade code space for less per-cell addressing and bit-selection work.

## Build

Prepare the shared assets from the parent player directory first:

```sh
node prepare-assets.cjs
```

Then, from this directory:

```sh
./build.sh
```

The script uses `kickass` on PATH. Set `KICKASS` to an alternate executable when needed. Shared assets are read from `../build/assets/` and are never regenerated by this build. Output is `build/player.prg`, with `build/main.sym` and `build/main.vs`.

## Presentation and inspection

Both full screen buffers and Color RAM are initialized. Playback uses hires text, white characters, black background, no sprites and no interrupts or music. A completed hidden screen becomes visible only at PAL raster wrap. There is no additional FPS limiter.

At `frame_done`, `frame_index` identifies the frame just presented. The index advances after that checkpoint. Frame 63 resets the actual packet pointer and index to frame 0. `frame_counter` is 16 bits. All frame-header parsing, PackBits expansion, bit-map reading and glyph writes execute between `render_start` and `render_end`.

## Memory and size

| Region | Purpose | Bytes |
| --- | --- | ---: |
| `$0400..$07ff`, `$0c00..$0fff` | Alternating screen buffers | 2,048 |
| `$1000..$103b` | Expanded fill bits | 60 |
| `$2000..$27ff` | Fixed mathematical font | 2,048 |
| `$2800..$2fff` | Eight fill-bit lookup planes | 2,048 |
| `$3000..$31aa` | Startup, parsing, PackBits and presentation control | 427 |
| `$4000..$8a97` | Unmodified compact HC64 file | 19,096 |
| `$9000..$c657` | Two direct-store kernels | 13,912 |

Zero-page scratch occupies `$02..$13` (18 bytes). The load image ends below I/O and hardware vectors. The single-load PRG is 48,729 bytes including its two-byte load address and gaps between regions. The kernel and LUT bytes above are included in that footprint.

## Current PAL verification

`build/verification/verification.json` records the current smooth-motion program in PAL VICE at 100% speed, warp disabled. It checks 66 successive presentations, including the complete 64-frame cycle and `63 → 0 → 1`. All 66,000 screen bytes match the independent HC64 decoder, the font remains unchanged, and three actual VIC screenshots match the visible screen.

Render time is **12,765–13,706 clocks**, with a **13,537.71-clock mean**, including VIC bus stalls. Every presentation fits one PAL field: **50.1245 median FPS**. Presentation timing includes raster waiting. There is no music or IRQ workload.
