# Offline fill and edge format study

The reference consists of 256 complete character screens per model, generated by the same verified native-model arithmetic. Glyph0 is empty, glyph15 is solid, all other codes are edge glyphs. Screens, font and the native renderer are immutable inputs.

`common.cjs` supplies `getCorpus()` with `models.checker` and `models.football` arrays, `layouts`, source hashes, and validation helpers. Layouts are full screen1000, fixed rectangle600, and circle475. Rectangle metadata is4 bytes once; circle metadata is50 bytes once (start column and length for each of25rows). A cropped decoder starts both screen buffers with black outside the fixed layout.

The fill encoder must preserve exact0/15 cells. Edge cells may use either fill bit, since the edge layer overwrites them. Each edge decoder must restore every exact edge code and leave all other cells unchanged, unless its declared format explicitly covers additional ordinary cells.

Fill API: `codecs=[{name,encode(screen,indices),decode(payload,count)}]`. Decode returns binary0/1 values. Edge API: `codecs=[{name,encode(screen),decode(payload,outputScreen)}]`. Edge decode writes into the supplied1000-byte screen. Unified alternating formats expose independent full-frame encode/decode functions and count all their tags and prefixes.

Measurements count actual serialized bytes, including record counts, directions, lengths, escapes and palettes. The reference combined container will use two16-bit payload lengths per frame (4bytes), followed by the fill and edge payloads. Codec IDs and layout are selected in a shared header. An adaptive per-frame codec option needs another mode byte and must charge it. Optional random-access tables, shared font and metadata are reported separately. A future self-delimiting decoder may remove some framing, but no such saving is presumed here.

Every full screen must round-trip exactly. Include synthetic empty/solid frames, adjacent edge glyphs, phase repair using a real blank/full cell, long runs and end-of-frame cases. These are packing and decoding measurements on the host; no C64 timing or FPS claim is implied.
