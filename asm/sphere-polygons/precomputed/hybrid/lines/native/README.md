# Callable native Q8 line primitive

`main.asm` implements a small 6502 line drawer using the mathematical Q8
greater-or-equal and equality masks generated by
[`geometry-lines.cjs`](../geometry-lines.cjs). It advances a slope/phase state
once per major character coordinate, converts each partial 8-probe mask through
the fixed glyph lookup, and writes that glyph into a caller-provided 40×25
character buffer. It does not search glyphs, render a pixel bitmap, or read a
captured sequence of character codes.

This is a callable primitive, rather than a complete movie player. The caller
provides fill cells and resolves corners, crossings or silhouette exceptions.
When several polygon boundaries share a cell, simply writing their independent
glyphs in succession does not compute their combined mask. The full checker
format and composition strategy are separate work.

## ABI

Call `JSR draw_line` with a 16-bit destination screen pointer in `$02/$03` and
these byte variables set:

| Input | Meaning |
| --- | --- |
| `line_n` | Signed slope numerator, −8 through +8; denominator is 8. |
| `line_axis` | 0: major X/minor Y; 1: major Y/minor X. |
| `line_phase` | Anchor phase, 0–7. |
| `line_u`, `line_v` | Anchor major and minor character coordinates. |
| `line_positive` | 1 selects the positive half-plane; 0 selects the negative half-plane. |
| `line_include` | 1 includes probes exactly on the line; 0 excludes them. |
| `line_major_start` | First major character coordinate. |
| `line_length` | Number of major character coordinates to process; 0 is a no-op. |

The inputs match the decoded fields from `decodeDescriptor` and the start/length
arguments of `lineGlyphSequence`. For axis 0, the major range must fit 0–39 and
the anchor minor coordinate 0–24. For axis 1, those ranges are 0–24 and 0–39.
Require `major_start + length` to remain within the relevant major range. These
are caller preconditions, not an input-validation protocol.

The routine uses `$02–$17`: 22 zero-page bytes including the screen pointer.
It clobbers A, X, Y and processor flags. It preserves the input variables,
code and lookup tables. The destination pointer need not be page-aligned.
Cells with masks 0 or 255, cells outside the screen, and cells outside the
requested major interval are left unchanged. Finite length trims whole major
character coordinates; it does not encode a sub-character endpoint clip.

For a probe with local major/minor coordinates `a,b` in tile `M,N`, the direct
integer reference equation is:

```text
D = 8 × (8 × (N − v) + b) − n × (8 × (M − u) + a) − 8 × phase
```

The selected half-plane tests the sign of D, with equality handled explicitly.
The eight probes, in bit order, are `(1,1), (4,1), (6,1), (1,4), (6,4), (1,6),
(4,6), (6,6)`. Only partial masks `0 < mask < 255` produce stores.

Before drawing, the routine walks the normalized phase from the anchor to
`major_start`, including negative movement. During drawing it adds `n` to the
phase each character step. Since `|n| ≤ 8`, at most one phase carry or borrow
updates the minor base. This avoids a multiplier and preserves signed slopes
and exact inclusive/exclusive ties.

## Build and conformance proof

The generated shared assets in `lines/build/` must already exist. Build from
the repository root:

```sh
rtk proxy sh asm/sphere-polygons/precomputed/hybrid/lines/native/build.sh
```

The output is `build/line.prg` plus `main.sym` and assembler debug data. This
PRG is a loadable routine module, not a BASIC/VIC setup demo. A caller using the
existing mathematical font can load it and call the exported `draw_line` label.

Run the actual assembled instructions against the independent integer equation:

```sh
rtk proxy env PYTHONPATH=/tmp/disco-sid-analysis-py65 python3 \
  asm/sphere-polygons/precomputed/hybrid/lines/native/verify.py
```

The verifier derives expected masks directly from the equation above, not from
`maskAt`, `lineGlyphSequence` or an encoder's cached line output. It checks every
loaded GE/EQ table entry, all Q8 slope/phase/axis/side/tie combinations, finite
intervals including length zero, and the actual line descriptors from all 64
smooth checker poses. Each call starts with varied nonempty buffer contents;
all 1,000 character bytes, adjacent guard bytes, machine code and lookup tables
are checked. Both aligned and unaligned destination pointers are exercised.
The report is written to `build/verification.json`.

The assembled proof passed **6,400 calls and 6,400,000 exact screen bytes**,
including 127,968 partial-glyph writes. It covers 1,088 full-range synthetic
lines, 1,088 finite-range cases and all 4,224 checker line descriptors across
the 64 poses. This proves each isolated line primitive against its mathematical
descriptor, rather than claiming that independent line writes compose an exact
checker image.

## Memory and measurement scope

| Region | Purpose | Bytes |
| --- | --- | ---: |
| `$3000` onward | Routine and nine input bytes | 283 |
| Immediately after routine/input bytes | Slope and row address constants | 84 |
| `$4000–$432f` | Q8 greater-or-equal masks | 816 |
| `$4400–$472f` | Q8 equality masks | 816 |
| `$4800–$48ff` | Coverage-mask to font-glyph lookup | 256 |

Meaningful code, state and constants total 367 bytes; mathematical mask/glyph
lookups total 1,888 bytes, for 2,255 loaded bytes before address gaps. The fixed
2,048-byte font and 1,000-byte destination screen belong to the caller. No
per-frame strings or screen images are embedded in this module.

The actual loadable PRG is 6,402 bytes including address gaps and load address.
Its SHA-256 is
`2be53c2463c06a8daab2461d7b8c624c04ba1c4ca20da19cf5dd71bd5c6efd33`.

| Callable-line cases | Minimum cycles | Mean cycles | Maximum cycles |
| --- | ---: | ---: | ---: |
| All synthetic full-range combinations | 6,682 | 11,452.60 | 15,534 |
| Synthetic finite intervals, including no-ops | 12 | 1,986.69 | 4,677 |
| Actual checker descriptors over full major ranges | 6,797 | 11,308.84 | 15,910 |

The proof records CPU instruction cycles per line, including anchor seeking,
mask classification, clipping, lookup and stores. Plain py65 excludes VIC bus
stalls and display presentation. These numbers are primitive costs, not a
full-checker runtime estimate or native movie FPS measurement.
